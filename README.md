# commissura

Turn raw clinical material — HL7 v2 lab messages, free-text reports, DICOM
imaging metadata — into a standardised, de-identified, research-ready dataset
with a verifiable manifest.

BIDS gives neuroimaging a shared layout. Nothing equivalent links laboratory
results and clinical reports to the same subject. `commissura` builds that bridge.

> **All clinical data in this project is synthetic.** No real patient data ever
> enters this repository, in any form. Every fixture is generated by
> `commissura generate`.

## Why

EU Regulation 2025/327 (European Health Data Space) makes secondary use of
health data a legal obligation for data holders from March 2029. Hospitals,
research institutes and laboratories will have to produce structured,
de-identified, documented datasets. `commissura` is a local command-line tool that
does exactly that — no service to deploy, no network component, no accreditation
required.

## Install

Requires Python 3.11 or newer.

```bash
pip install commissura
```

From a checkout, for development:

```bash
uv venv
uv pip install -e ".[dev]"
```

## Commands

| Command | What it does | Status |
| --- | --- | --- |
| `commissura generate` | Write a synthetic raw clinical corpus, with injectable defects and ground-truth PHI annotations | available |
| `commissura defects` | List the defects the generator can inject, and the real-world cause of each | available |
| `commissura validate` | Check a dataset against the layout and report what is missing | available |
| `commissura rules` | List every validation rule and what it checks | available |
| `commissura keygen` | Create a pseudonymisation key | available |
| `commissura key-info` | Show a key's fingerprint, without revealing the key | available |
| `commissura build` | Pseudonymise a raw corpus into a dataset, with manifest | planned |
| `commissura risk` | k-anonymity report over participant attributes | planned |

Every command that reports anything accepts `--json`, so the tool composes
inside somebody else's pipeline without being screen-scraped.

### `commissura generate`

```bash
commissura generate --subjects 25 --seed 42 --out ./raw
```

Produces a corpus that looks like three separate hospital exports, because that
is how such data actually arrives — and linking them is the problem this project
exists to solve:

```
raw/
  lab/        ORU^R01 messages, one file per panel
  reports/    free-text radiology and discharge reports
  imaging/    DICOM-style metadata sidecars
  _generator/
    generation_manifest.json   seed, counts, tool versions, defects applied
    phi_annotations.json       every identifier, with file and character offsets
```

The generated material **deliberately contains synthetic identifiers** — names,
codici fiscali, absolute dates, addresses, referring physicians. That is the
point: you cannot test a de-identifier on data that has nothing to remove.

`phi_annotations.json` is the ground truth. Because the generator records where
it put every identifier, de-identification recall becomes measurable rather than
assumed — which matters, since general-purpose LLM tools have been shown to miss
over half of clinical PHI.

Offsets are character positions into the UTF-8 decoded file, over a half-open
interval, so `text == content[start:end]` always holds. `--verify`, on by
default, re-reads every file from disk and checks it.

#### Reproducibility

The same seed and the same tool version always produce the same corpus, and the
guarantee is stronger than that:

```bash
commissura generate -n 3  --seed 11 -o small
commissura generate -n 30 --seed 11 -o large   # the first 3 subjects are identical
```

Subject *n* does not depend on how many subjects were requested, because each
one is generated from its own stream derived from the master seed. So a bug
report that says "subject 347 has a negative haemoglobin" stays reproducible
from the seed alone, without shipping the corpus.

#### Defect injection

`--defect-rate` controls the probability that any given defect opportunity is
taken. Every injected defect is recorded in the manifest with the file it landed
in, which is what makes validator development measurable: run the validator,
compare what it reported against what was injected, read off the misses.

`--defect-rate 0` produces undamaged data — but not *easy* data. Identifiers
written inside clinical sentences are how reports are written, not a defect, so
they are always present. Anyone who scrubs the header fields of a clean corpus
and scores perfectly has learnt something useful.

### `commissura validate`

```bash
commissura validate ./dataset
```

Reports everything it finds rather than stopping at the first problem. The
question the command answers is *what is missing*, in the plural, and a
validator that answers one item at a time turns a single review into a dozen
round trips.

```
ERROR   DS002 participants.tsv: required file participants.tsv is missing from the dataset root
        Every dataset must carry participants.tsv.
ERROR   DI003 sub-a3f9c21b4e07/ses-01/reports/sub-a3f9c21b4e07_ses-01_run-01_report.txt:
        contains what looks like an absolute date: '12/03/2023'
        A date written inside a sentence is invisible to field-based scrubbing.

NOT CONFORMANT: 2 error(s), 0 warning(s), 0 notice(s) from 39 rules
```

Exits 0 when the dataset conforms and 1 when it does not. Warnings do not affect
the exit code unless `--strict` is passed: a dataset can conform and still have
things worth improving, and a validator that rejects for stylistic reasons gets
switched off.

`commissura rules` prints the whole rule set. **The rule set is the schema** —
there is no separate specification document to drift out of date.

| Prefix | Rules | What they check |
| --- | --- | --- |
| `DS` | 10 | The skeleton: required files, the dataset description, the manifest |
| `PT` | 9 | `participants.tsv`, and its agreement with the directories on disk |
| `NM` | 6 | Directory and file naming, and the BIDS entity grammar |
| `LB` / `RP` | 6 | The `lab` and `reports` datatypes this project adds |
| `DI` | 8 | The de-identification invariants the layout promises |

The `DI` rules are the ones that justify the command existing, and they are
written as *structural* requirements rather than as advice. A dataset carrying a
real calendar date is not weakly de-identified, it is malformed, because the
layout states that time is expressed only as `day_offset` from each subject's
own baseline. Intervals stay exact; the calendar anchor is gone.

`DI003` is the one that earns its keep: it scans report prose, where a date
inside a sentence — *si confronta con il precedente esame del 12/03/2023* — is
invisible to anything that scrubs by field.

#### Written before `build`, on purpose

`validate` exists before the command that produces datasets. That ordering
forces the schema to be precise: the layout lives in one module,
[`commissura/layout.py`](src/commissura/layout.py), and the validator is derived
from it, so `build` will have a specification to satisfy instead of defining one
by accident as it goes.

```
dataset/
  dataset_description.json
  participants.tsv
  sub-<label>/ses-<n>/
    anat/ pet/ lab/ reports/
  derivatives/
  .deident/
    manifest.json
    risk_report.json
```

`lab/` and `reports/` are the extension. They follow BIDS naming rather than
inventing new rules, so a BIDS validator will not recognise them and will not be
confused by them either.

### Pseudonymisation

One secret key, everything derives from it, the key never enters the dataset.

```bash
commissura keygen --out ~/.commissura/key
export COMMISSURA_KEY_FILE=~/.commissura/key
```

```
subject_id  = HMAC-SHA256(key, "subject|" + national_id)[:12]   -> sub-a3f9c21b4e07
date_offset = HMAC-SHA256(key, "offset|"  + subject_id) % 730 - 365
dicom_uid   = "2.25." + int(HMAC-SHA256(key, "uid|" + original_uid))
```

Three properties, each with a tempting wrong alternative:

**Keyed, not plain.** `sha256(national_id)` would be useless. A codice fiscale
encodes a name, a birth date, a sex and a place of birth, so the space is small
enough to enumerate: anyone with a candidate list hashes it and reverses the
dataset over a weekend. With an HMAC they need the key.

**Domain-separated.** Every derivation prepends a label naming what is being
derived. Without it, the same string used as a patient id and as an accession
number would produce the same pseudonym, and a value observed in one role could
be replayed in another.

**Deterministic across runs and modalities.** The same person gives the same
`sub-` label today and in three years, in the lab branch and the imaging branch.
That is the only thing linking three separate hospital exports.

Subject labels keep 48 bits of the digest. Collisions are a theoretical concern
rather than a practical one, but the pseudonymiser records what it has issued
and **raises** on a collision rather than silently merging two people.

#### The key is never a command-line argument

There is no `--key <value>` option, here or anywhere. A key passed as an
argument lands in shell history, in `ps` output for every other user on the
machine, and in the logs of any CI system that runs the command. The only ways
in are a key file and an environment variable naming that file — not holding the
key, since the process environment is readable from `/proc` and gets dumped
wholesale into crash reports.

What is printed and recorded is the key's **fingerprint**: a domain-separated
digest that identifies the key without carrying it. It answers the question
somebody asks years later — were these two datasets built from the same key, and
are they therefore linkable? — without answering what the key is.

On POSIX the key file is created mode 0600. On Windows that mode is largely
ignored, so `keygen` reports `owner-only access NO` and says what to do instead,
rather than implying a protection it did not apply.

#### Two different time mechanisms

| | What it is | Where it appears |
| --- | --- | --- |
| `day_offset` | Integer days from the subject's own baseline. Needs no key — it is a subtraction. | **In the dataset.** The only time representation it carries. |
| `date_offset` | Per-subject ±365-day HMAC shift. Preserves intervals exactly, destroys the calendar anchor. | **Never in the dataset.** For values that must stay a syntactically valid date for a downstream tool, notably DICOM `StudyDate` on the way into `dcm2bids`. |

The shift differs per subject deliberately: one offset for the whole cohort
would preserve cross-subject alignment, and a single known date anywhere would
then unshift everybody.

### Synthetic by construction

"Probably not real" is not good enough for clinical identifiers, so each one is
placed where no authority assigns:

| Identifier | Why it cannot be real |
| --- | --- |
| Codice fiscale | Place-of-birth code uses an `X` prefix; municipalities are assigned `A`–`M` and foreign states `Z`. The checksum is still valid, so the values exercise a real validator. |
| Telephone | Subscriber part starts with `0`, which is never assignable after an Italian area code. |
| Email | `.invalid` is reserved by RFC 2606 and can never be registered. |
| DICOM UID | The `2.25` arc holds UUIDs as integers, needs no registration, and collides with nobody. |
| Institutions | Invented names at invented addresses, every one marked `SINTETIC`. |

## Development

```bash
uv venv && uv pip install -e ".[dev]"
```

```bash
pytest && ruff check . && ruff format --check . && mypy
```

`pytest` measures branch coverage on every run and fails below 99%. The
threshold is enforced in configuration rather than offered as a flag, because a
threshold that applies only when somebody remembers to ask for it is not one.
To skip it while iterating on a single test:

```bash
pytest --no-cov tests/test_hl7.py
```

It is a regression floor, not a target. Coverage says a line ran, not that it
was checked, so the suite is written to pin the decisions that are easy to undo
by accident: that `--defect-rate 0` reports no defects, that a clean corpus is
still hard to de-identify, that institution names carry a synthetic marker with
no exceptions, that HL7 files contain no line feed, and that `verify_corpus`
actually fails when a file is altered.

The floor is Python 3.11, and `mypy` is configured against it, so a standard
library call added in a later version is caught even when the tests run on a
newer interpreter — this is how `Path.read_text(newline=...)`, which is 3.13 and
later, was caught before it shipped. To exercise the floor itself:

```bash
uv run --python 3.11 pytest
```
